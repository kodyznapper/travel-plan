# Travel Plan (แผนเที่ยว)

เว็บแผนเที่ยวแบบ interactive ใช้ดูบนมือถือระหว่างเที่ยว สร้างจากไฟล์ markdown ที่เขียนตาม template (`data/travel-plan-template.md`)

**โมเดลการใช้งาน:** เจ้าของ (Kody) แก้ไขแผนได้คนเดียว ทุกคนที่ได้ลิงก์ **ดูได้อย่างเดียว** (ติ๊กเช็กลิสต์ของตัวเองได้ในเครื่องตัวเอง)

แผนที่ใช้อยู่ตอนนี้: Taiwan Trip 2026 (12–17 พ.ย. 2026, 8 คน)

> รายละเอียดทางเทคนิค กฎการเขียนโค้ด และสถานะงานแบบละเอียดอยู่ใน [CLAUDE.md](CLAUDE.md)
> **ทุกครั้งที่เพิ่ม/เปลี่ยน feature ต้องอัปเดตทั้งไฟล์นี้และ `CLAUDE.md`**

## Feature ที่ใช้ได้แล้ว

- Dashboard + ปฏิทินรายเดือน
- ภาพรวมทริป: เที่ยวบิน ที่พัก สิ่งที่ต้องจำตลอดทริป
- Timeline รายวัน (ย่อ/ขยายการ์ด) + **Today mode** (เส้น "ตอนนี้")
- Metro map ต่อวัน/ทั้งทริป + สีตามสายรถไฟ/MRT พร้อม legend "สายที่ใช้วันนี้"
- เช็กลิสต์เตรียมของ และ To-do
- ข้อมูลอ้างอิง: เบอร์ฉุกเฉิน ประโยคภาษาท้องถิ่น การ์ดแท็กซี่ (เปิดเต็มจอได้)
- สลับภาษา TH/EN และธีม dark/light
- **โหมดเจ้าของ:** ซ่อนเครื่องมือแก้ไข/นำเข้า/ส่งออก/หน้าวางแผนจากผู้ชม (ตั้งค่า → แตะบรรทัดเวอร์ชัน 7 ครั้ง)
- นำเข้า .md/.json พร้อม preview, ส่งออก .md/.json, ดาวน์โหลด template
- **(v2.2.2) Google Apps Script:** แผนอยู่ในไฟล์ `.md` ใน Google Drive ของเจ้าของ ทุกคนเปิดลิงก์เดียวกันแล้วเห็นแผนล่าสุด เจ้าของแก้ในหน้าเว็บแล้วกด **"บันทึกขึ้น Drive"** (ต้องใส่รหัสแก้ไข ซึ่ง server ตรวจ) ผู้ชมไม่เห็นหัวข้อ "วางแผน" · กันบันทึกทับของที่ใหม่กว่า · สำรองไฟล์เดิมทุกครั้งที่บันทึก

## วิธีเอาขึ้น Google Apps Script

ใช้ไฟล์ 2 ไฟล์จาก `dist/gas/` (มีอยู่ใน repo แล้ว หรือสร้างใหม่ด้วย `make build`)

### ครั้งแรก (ประมาณ 10 นาที)

1. เปิด https://script.google.com → **New project** → ตั้งชื่อ เช่น `Travel Plan`
2. **Code.gs:** ลบโค้ดที่มีอยู่ แล้ววางเนื้อหาทั้งหมดของ `dist/gas/Code.gs` → กด 💾
3. **index.html:** กด **+** ข้าง Files → **HTML** → ตั้งชื่อ `index` (ไม่ต้องพิมพ์ .html) → ลบของเดิม วางเนื้อหาทั้งหมดของ `dist/gas/index.html` → กด 💾
4. **ตั้งรหัสแก้ไข:** ⚙️ Project Settings → เลื่อนลงไป **Script Properties** → Add script property
   - Property: `EDIT_KEY`
   - Value: รหัสยาวๆ ที่เดายาก (แนะนำ 20 ตัวขึ้นไป เช่นวลีหลายคำผสมตัวเลข) จดไว้ในที่ปลอดภัย **อย่าใส่รหัสนี้ในไฟล์ไหนใน repo**
5. **สร้างไฟล์แผนใน Drive:** กลับไปที่ Editor → เลือกฟังก์ชัน `setup` ในแถบด้านบน → **Run**
   - ครั้งแรก Google จะขอสิทธิ์ → Review permissions → เลือกบัญชี → ถ้าขึ้น "Google hasn't verified this app" ให้กด **Advanced → Go to Travel Plan (unsafe)** (เป็นสคริปต์ของคุณเอง ขึ้นแบบนี้ปกติ) → Allow
   - ดู Execution log ต้องเห็น `Created plan file: travel-plan.md` และ `EDIT_KEY is set`
   - ใน Drive จะมีไฟล์ `travel-plan.md` และโฟลเดอร์ `travel-plan backups` (ไม่ต้องแชร์ให้ใคร)
6. **Deploy:** ปุ่ม **Deploy → New deployment** → ⚙️ Select type → **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - กด Deploy → คัดลอก **Web app URL** (ลงท้าย `/exec`) นี่คือลิงก์ที่แจกเพื่อน
7. **ปลดล็อกโหมดเจ้าของในเครื่องคุณ:** เปิดลิงก์ → ⚙️ ตั้งค่า → แตะบรรทัด `แผนเที่ยว v…` 7 ครั้งติด → เปิดสวิตช์ **โหมดวางแผน** → แถว "รหัสแก้ไข" กด **ใส่รหัส** → ใส่รหัสจากข้อ 4 (ทำแบบนี้ในทุกเครื่องที่จะใช้แก้ เช่น มือถือ + โน้ตบุ๊ก)

### อัปเดตโค้ดครั้งต่อไป

1. `make e2e` ผ่าน → วาง `dist/gas/Code.gs` และ `dist/gas/index.html` ทับของเดิมใน Apps Script → 💾
2. **Deploy → Manage deployments** → กด ✏️ ที่ deployment เดิม → Version: **New version** → Deploy
3. **ห้ามกด New deployment** จะได้ URL ใหม่ ลิงก์ที่แจกไปแล้วจะไม่อัปเดต

แผนใน Drive ไม่เปลี่ยนตามการอัปเดตโค้ด (seed ใน `Code.gs` ใช้แค่ตอน `setup()` ครั้งแรก)

### วิธีแก้แผน

- **ในหน้าเว็บ (แนะนำ):** โหมดเจ้าของ → ✏️ แก้ไข → แก้ → กด **บันทึกขึ้น Drive** (ระหว่างนี้แถบด้านบนเป็นสีส้ม = เพื่อนยังเห็นเวอร์ชันเดิม)
- **เปลี่ยนทั้งแผนด้วยไฟล์ .md ใหม่:** นำเข้าไฟล์ (ชื่อทริป + วันเริ่มต้องตรงกับแผนเดิม) → เลือก **เขียนทับแผนเดิม** → กดบันทึกขึ้น Drive
- **แผนที่อยู่แค่ในเครื่อง** (เช่น นำเข้าตอนที่ Drive ยังโหลดไม่ได้) จะมีแถบส้ม "ยังไม่ได้อยู่บน Drive" กด **ใช้แผนนี้เป็นแผนบน Drive** แผนบน Drive จะถูกแทนที่ด้วยแผนนี้ (ของเดิมสำรองไว้ก่อน)
- **แก้ไฟล์ใน Drive ตรงๆ** ก็ได้ ถ้าตอนนั้นในหน้าเว็บมีการแก้ที่ยังไม่บันทึก เว็บจะถามว่าจะใช้อันไหน

## แก้ปัญหา

- **หน้าค้าง "กำลังโหลดแผน…"** หรือขึ้น **"ไฟล์แผนบน Drive ว่างเปล่า"**: เปิดไฟล์ `travel-plan.md` ใน Drive ดูว่ามีข้อความไหม ถ้าว่าง ให้ใช้วิธีใดวิธีหนึ่ง: (ก) รัน `setup` อีกครั้ง จะเติมไฟล์ว่างด้วยแผนที่ฝังมากับโค้ด หรือ (ข) นำเข้าไฟล์ .md ในหน้าเว็บ แล้วกด **ใช้แผนนี้เป็นแผนบน Drive**
- **ดูว่า server ทำงานไหม:** Apps Script → ⏱ Executions ดูแถว `getTrip` / `saveTrip` ถ้า Failed คลิกดูข้อความ error
- **ข้อความ error ในหน้า** ค้างอยู่ที่แถบส้มด้านบนแผน (เจ้าของ) หรือการ์ดหน้าแรก (ผู้ชม) พร้อมปุ่ม "ลองใหม่"

## สิ่งที่ควรรู้

- **ด้านบนหน้าจะมีแถบของ Google** "This application was created by a Google Apps Script user" เอาออกไม่ได้ (กฎของ Google)
- **ความปลอดภัย:** ตัวป้องกันจริงคือรหัสที่ server ตรวจ ไม่ใช่โหมดเจ้าของ (โหมดเจ้าของเป็นแค่ตัวซ่อนปุ่ม) ผู้ชมเห็นทุกอย่างในแผนยกเว้นหัวข้อ "วางแผน" และ `<!-- comment -->` อย่าใส่ข้อมูลส่วนตัว (เลขพาสปอร์ต, เลขจอง) ในส่วนอื่นของแผน
- **ถ้ารหัสหลุด:** เปลี่ยน `EDIT_KEY` ใน Script Properties ได้ทันที เครื่องที่จำรหัสเก่าไว้จะบันทึกไม่ได้จนกว่าจะใส่รหัสใหม่
- **ใส่รหัสผิด 10 ครั้งใน 10 นาที** ระบบล็อกการบันทึก 10 นาที (นับรวมทุกคน) การดูแผนไม่ถูกล็อก
- **สิทธิ์ Drive:** สคริปต์ขอสิทธิ์อ่าน/เขียน Drive ของคุณ (Google ไม่มีสิทธิ์ที่แคบกว่านี้สำหรับ `DriveApp`) แต่โค้ดแตะแค่ไฟล์แผนและโฟลเดอร์ backup
- **โฟลเดอร์ backup** โตขึ้นทุกครั้งที่บันทึก ลบไฟล์เก่าเองได้
- **ติ๊กเช็กลิสต์** เป็นของแต่ละเครื่อง ไม่ขึ้น Drive ไม่เห็นกันข้ามคน
- **ลิงก์ `/dev`** (Test deployments) ใช้ได้เฉพาะคุณ แจกเพื่อนต้องใช้ `/exec`
- **โควตา:** Gmail ส่วนตัวมีโควตาการรันต่อวัน กลุ่ม 8 คนน่าจะไม่ถึง (ยังไม่ได้ตรวจตัวเลขจริง) หน้าเว็บไม่ poll จะโหลดใหม่เมื่อเปิดหน้าหรือกลับมาที่แท็บหลังห่างไป 5 นาที

## วิธี build และทดสอบ

```bash
make build    # สร้าง dist/travel-plan.html และ dist/gas/
make test     # parser round-trip + i18n coverage + logic ของ Code.gs (GAS จำลอง)
make e2e      # build + test + Playwright ทั้งชุด (รวมหน้า GAS กับ GAS จำลอง)
make serve    # เปิดดูที่ http://localhost:8000/travel-plan.html
```

e2e ต้องติดตั้งครั้งแรก: `pip install playwright && playwright install chromium` (ถ้า pip ติดตั้งลงระบบไม่ได้ ดูวิธีใช้ venv ใน CLAUDE.md ข้อ 5)

เทสต์ใช้ GAS จำลอง (`tests/gas/`) ที่รัน `Code.gs` จริงกับ Drive/Properties ปลอม เช็กได้ว่า logic ของเราถูก แต่ไม่ได้เช็กพฤติกรรมของ Google จริง ต้องทดสอบมือตาม checklist ด้านล่างหลัง deploy
